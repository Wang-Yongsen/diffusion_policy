## zarr 缺口修复

### 配置与入口

生成入口为本项目 `scripts/finalize_recording.py` 与 `scripts/convert_recording.py`，唯一转换实现位于 `third_party/bimanual_teleop/recording/convert.py`。[通用转换配置](../diffusion_policy/config/recording_conversion.yaml)与[旧会话配置](../diffusion_policy/config/recording_conversion_tianji_rail_20260924.yaml)均在本项目；Python API 和 CLI 保留可选 `--conversion-config`，不传时保持严格模式，显式 `mode: repair` 才启用修复。会话复核结论只用于对应来源，输出必须为新路径。必要的原始数据格式、整理及归档规则已经提取到[数据说明](../docs/tianji-rail/data-preparation.md)，无需阅读或访问采集项目。

| 参数 | 默认值 | 注释需要说明的含义 |
| --- | --- | --- |
| `mode` | `repair` | 固定时间网格与短缺口修复 |
| `target_fps` | `30` | 输出时间网格频率 |
| `max_missing_camera_frames` | `2` | 每路相机最多连续修复两个未正常匹配的采样点；30 Hz 下两帧缺失通常对应约 100 ms 的真实帧间隔 |
| `camera_match_tolerance_ms` | `20` | 正常图像匹配的最大时间差 |
| `max_state_interp_gap_ms` | `100` | 状态插值需要的两端实测数据最大间隔 |
| `max_command_age_ms` | `50` | 最近一次成功提交指令的最大允许年龄 |
| `pause_policy` | `checked_compress` | 暂停区间独立对齐；仅对通过连续性复核的接缝压缩时间并合并。未复核或未通过时保留边界 |
| `pause_offset_tolerance_ms` | `100` | 来源时间与压缩时间偏移突变的识别阈值；应高于时钟抖动、低于目标暂停长度，三路归属不一致时报错 |
| `pause_reviews` | `{}` | 来源名与原始0起行号取报告的 source_episode／pauses.after_main_row；merge和reason人工复核填写，未复核保留边界，结论不可直接复用。详见[取值说明](../wys/2026-10-05-pause-reviews/usage.md) |

配置写明单位和默认值；提高相机修复上限会延长旧画面复用时间，不会恢复实际缺失图像。相机、状态与命令阈值分别控制各自的数据质量，不能互相替代。

### 时间轴与修复规则

1. 先确定同一 episode 内的持续录制区间。在每个区间内以第一帧主相机时间为锚点建立 30 Hz 网格，时间戳由索引直接计算到纳秒，避免逐步累加产生漂移。流匹配和插值不跨 episode、原始暂停或明确的时间戳异常；暂停两侧在独立对齐后按下述规则检查是否可拼接。
2. RGB 优先采用与网格时刻相差不超过 20 ms 的最近真实帧。内部未匹配区间长度不超过配置上限时，复用该时刻之前最近的真实图像，且图像年龄不得超过 `(max_missing_camera_frames+1)/target_fps` 秒。超过上限的整段未匹配区间不修复；不在超长缺口起点先保留两帧伪连续数据。
3. 每路相机分别判断缺口；填补必须处于有效真实数据之间，不延伸首尾覆盖范围。三路图像、全部必需状态和动作同时可用，该网格时刻才能发布。
4. 状态使用原始流的直接相邻有效测量插值；位置、关节和力线性插值，四元数姿态用 SLERP。两端间隔超过配置值、数值无效或跨暂停时拒绝，不跳过异常测量寻找更远端点，不向观测范围外推。
5. 动作仍采用网格时刻之前最近一次成功提交的指令，检查指令年龄和有效性。动作不做线性插值，也不移动标签索引。
6. 首尾缺少覆盖时裁剪；长缺口、状态异常、指令过期及未通过连续性复核的暂停仍切段。相邻有效网格点属于同一连续片段，成功填补的内部短缺口不再产生边界。

历史暂停通过相机 `source_time_ms` 与压缩后 `time_ns` 的偏移突变识别，结合可用事件核对。三路相机的暂停前后归属共同确定允许匹配和插值的区间；归属不明确的边缘数据裁剪。时间倒退或时钟重置不得当成普通缺帧处理。

### 脱合／接合暂停的最终策略

当前暂停识别、两侧独立对齐、人工复核与条件拼接的流程及时间轴示意见[暂停接缝策略图示](../wys/2026-10-05-pause-reviews/strategy.md)。采集时移除等待时间与离线允许跨接缝采样是两个判断；暂停期间不生成过渡样本，只有明确复核通过且两侧有效时才合并接缝。

采用“先识别和复核，满足条件则压缩暂停并拼接”的策略，不因遥操作参考重建而一律分段。保存的机械臂／手关节目标为绝对关节角；当前 EEF 模式的机械臂动作是各自基座系中的绝对末端位姿。重建操作者映射参考不会改变这些标签的坐标语义，但目标值可能重设，需与实测状态分开检查。

- 普通短采样缺失：仍按最多两帧的配置补齐，并在有效性检查通过后保持连续。
- 无完整暂停记录的历史数据：检查暂停两侧的实测末端、机械臂关节、手关节及绝对目标变化，并复核三路图像中的导轨、抓持和场景衔接；确认没有回位、故障或人工改变物体状态造成的中断。首版不凭端点数值接近自动认定整个暂停静止；阶段 0 为各接缝保存明确的合并／保留边界决定和依据，未经复核默认保留边界。
- 通过复核的接缝：保留两侧各自已对齐的真实来源样本，移除暂停等待时长，并将后侧首个样本安排在前侧末个样本的下一训练步，使训练时间保持 30 Hz；删除这一接缝的 `segment_ends` 边界。不是为数秒暂停复制数十帧图像，也不在线性插值中跨越没有原始记录的暂停。真实已提交目标若发生重设，保留这个变化，不生成中间控制指令。
- 未通过复核或证据不足：保留片段边界。若未来暂停期间有完整有效记录，可按原始状态和指令重采样，但不能据目前只有两端的数据推定期间轨迹。

保留逐样本来源时间和训练时间映射、暂停时长、拼接位置、复核结论及目标切换信息。指令新鲜度在原始来源区间内判断，不能通过压缩时间把过期指令变成有效指令。所有接缝均通过时，同一 episode 可成为一个连续训练片段；否则仍是一条原始演示下的多个连续片段。

### 格式、追溯与发布

- 保持 schema v2 的边界约定：`meta/episode_ends` 为原始演示，`meta/segment_ends` 为修复后连续训练区间；现有字段及 52 维动作布局不变。

```yaml
  _target_: diffusion_policy.policy.diffusion_transformer_hybrid_image_policy.DiffusionTransformerHybridImagePolicy
```

Transformer 参数默认采用参考配置起始值：`n_layer=8`、`n_cond_layers=0`、`n_head=4`、`n_emb=256`、`p_drop_emb=0.0`、`p_drop_attn=0.3`、`causal_attn=true`、`time_as_cond=true`、`obs_as_cond=true`。参数可在配置文件修改；显式设置 `pred_action_steps_only=false`，预测完整 16 步动作，再截取执行段。

| 配置项 | 默认值 | 功能与修改建议 |
| --- | --- | --- |
| `task.image_shape` | `[3,480,640]` | Dataset 输出通道、高、宽；当前三路原图均为宽640、高480，关闭缩放时尺寸须匹配原图。Dataset、Runner 与 RGB shape_meta 共用此尺寸 |

| `task.dataset.resize_interpolation` | `area` | 支持 area、bilinear、nearest；缩小优先 area，放大可用 bilinear，RGB 通常不推荐 nearest。关闭缩放时不执行 |
| `policy.crop_shape` | `null` | null 关闭裁剪；[高,宽] 启用训练随机裁剪，例如原图480×640时用 [432,576]。当前裁剪实现要求高宽分别严格小于输入，先检查是否裁掉导轨或手 |

### Dataset 与样本契约

- 继承 `BaseImageDataset`，实现样本读取、长度、验证集、归一化和动作读取接口；样本返回 `{"obs": ..., "action": ...}`。
- 三路 RGB 按需读取，当前关闭缩放并输出原图 `480×640`，HWC uint8 转 CHW float32 / 255；避免将全部原图解压进内存。状态选择 `robot_eef_pose` 和 `hand_joint`，不自动加入深度、力或机械臂关节观测。
- 原始末端为米和旋转向量弧度，手关节为弧度。动作顺序为左臂、右臂、左手、右手，共 52 维，首版不改为 rotation_6d。
- `horizon=16`、`n_obs_steps=2`、`n_action_steps=8`、`n_latency_steps=0`；`crop_shape=null`、视觉编码器使用 GroupNorm。
- 按原始来源划分训练和验证；按修复后的连续片段采样，并兼容旧格式边界和来源分组。Dataset 不复制首尾凑窗口，剩余不足 16 帧的片段不产生样本。转换器修复缺口与 Dataset 端点补齐是两个不同环节。
- 只用训练来源拟合状态和动作归一化参数；验证和独立评估使用训练保存的参数。缺口修复标记保留用于质检，不传入 Policy 的训练 batch。

### 训练与评估默认值

- 使用 GPU `cuda:0`，`seed=42`，关闭在线日志。冒烟 batch size 2、零 worker、关闭 persistent_workers；两个 epoch，每个最多两个训练 batch，学习率预热为 0，checkpoint 和采样检查每个 epoch 执行。Workspace 启动会实例化 Runner，因此阶段 4 先提供 OfflineRunner 的可实例化接口与空验证集跳过路径，阶段 5 再补全动作预测和指标计算。
- 正式训练 batch size 32、4个 worker、开启 persistent_workers，采用原图GPU实测推荐值；验证读取参数继承训练设置，验证不打乱。学习率预热及其他训练参数采用上面的 Transformer 默认值。新实验使用独立输出目录；恢复训练只使用同一配置和数据版本。
- 单演示 `val_ratio=0`，checkpoint 自动监控 `train_loss`；多演示 `val_ratio=0.1`，至少各保留一条训练和验证演示，自动监控 `val_loss`。文件只按 epoch 命名，不需随监控项手动修改。单来源请求留出验证时报错，空验证窗口不能用于监控 val_loss。
- Runner 继承 `BaseImageRunner`，提供 `run(policy) -> dict`；与训练使用相同来源划分和预处理，不重新拟合归一化器。按每个窗口执行预测，比较输出 `action` 与标签 `[1:9]`。
- 报告左右臂位置欧氏误差（毫米）、SO(3) 旋转测地误差（度）、左右手关节平均绝对误差（度），以及窗口数、执行步数和来源。汇总按有效预测步统计，并另给逐演示统计。
- 空验证集返回明确的跳过状态和原因，不伪造验证误差。通过现有 `eval.py` 生成 `eval_log.json`，Runner 另保存逐演示报告。

**实施：** 按下表职责实现三个模块与独立入口，直接复用设备 SDK、运动学、伺服和相机；没有新增 RPC、通用设备协议或第二个服务。相机/状态采集、GPU 推理、双臂、左右手及视频日志各自调度。默认影子模式，`--check-only` 不连接设备；运动需配置实测工作空间、使用 `--motion` 并手动开始。

观测使用完整历史覆盖、三路图像偏差/跨度与状态时效检查，位置线性/旋转 SLERP 插值，保留 checkpoint 预处理。动作保留 `t0+i/30`，丢弃过期步并校验整批目标；独立循环在覆盖耗尽、设备故障或部分拒绝时暂停。暂停清空未来队列，双臂请求停止，健康手保持最后已接受的目标；退出禁用手。新试验重置策略，停止时作废仍在推理的旧试验结果。

记录包括配置和版本、checkpoint SHA256、三路视频及逐帧时间、原始反馈到达标记、100 Hz FK/状态快照、预测、调度、SDK 事件、提交回执和停止原因。主机延迟报告含中位数/P95/P99/最大值；不声称已经测得物理响应延迟。成功率以所有开始的运动试验为分母，包含超时、接管与设备中止；影子试验不进入分母。实际硬件、工作空间与当前初始阈值仍待验收，没有开启未经标定的延迟补偿。

真机评估由 `diffusion_policy` 的独立入口启动，在统一环境中使用本地快照的相机、天机双臂执行器和无极双手驱动。GPU 推理与底层控制独立调度；如需子进程隔离，由入口通过同一环境的 `sys.executable` 启动，用户不需要另开一个环境或手动启动第二套服务。

实施分为以下步骤，每步保存对应验收结果：

1. **实时观测与接口测试。** 按固定相机序列号构建三路 RGB 历史，按实测双臂关节 FK 和双手关节反馈形成两次观测；核对 RGB 通道、分辨率、像素范围、左右顺序、关节顺序及坐标系。训练数据为 30 Hz，当前模型为 2 步观测、16 步完整预测、8 步返回动作；实际以 checkpoint 配置为准。在线对齐只使用当前已收到的数据，缺少有效历史或数据过旧时报告未就绪，不以零值凑观测。
2. **52 维绝对动作与控制运行时。** 按左臂 6、右臂 6、左手 20、右手 20 拆分动作。双臂 xyz／rotvec 转换为各自基座系下的法兰 `Pose`，双手构造有正确关节名和控制配置的绝对关节目标；复用已有约束和有效期检查。为策略控制实现独立于 Quest 与手套的接合、目标来源和健康检查，并补齐健康手持续保持循环。
3. **动作时序与停止测试。** 最新观测为 `t0` 时，当前 Policy 返回的第 i 步对应 `t0+i/30 s`；推理完成后筛选仍能提交的未来目标，短段执行后读新观测并重规划。保留独立的双臂／双手控制循环，测量真实周期和提交时差；新命令不能刷新过期策略目标的有效期。覆盖人工暂停、无新观测、推理卡顿、进程退出、通信断开、队列无有效未来目标及局部提交失败，清空未来动作并执行统一暂停处理。SDK 接受回执与实际执行反馈分别记录。
4. **无运动影子推理。** 不使能运动，读取真实图像和反馈、加载 checkpoint 做 batch=1 推理，测量包含图像传输、预处理、GPU 推理和调度的端到端延迟及尾部延迟；确认未来目标覆盖充足、输入与 Dataset 一致。训练吞吐不代替该项验收。
5. **短时闭环与正式任务评估。** 验证接合、停止、恢复及短时执行后，冻结模型、设备与部署配置、初始条件、成功判据和超时，再进行导轨抓取放置试验。每次新试验重置策略并清空旧队列；进程重启不自动恢复运动。正式成功率使用阶段 6 选定的 checkpoint。
6. **记录、报告与使用说明。** 保存 checkpoint 标识、依赖／SDK／配置版本、三路视频、实际状态、模型预测、计划及实际提交时刻、各设备回执和停止原因。首版由操作员判定导轨放置、释放与稳定结果，分别记录失败、超时、接管和设备中止；预先固定分母定义，生成逐次试验与成功率报告。同步更新两边 README、先前图示、启动及停止说明和本计划状态。

**产物与验收：** 独立真机入口与配置、实时环境和控制运行时、假设备与影子推理报告、停止及短时闭环证据、逐次视频与动作反馈记录、正式真机评估报告。训练任务继续使用 OfflineRunner；真机 Runner 仅由独立入口启动。

### 多频率观测与延迟验收

现有双臂控制循环为 200 Hz，双手控制为 120 Hz，双手反馈请求为 200 Hz（以 SDK 返回的生效值及实际到达间隔为准），三路 RGB 配置为 30 Hz。机械臂实际反馈频率需要测量；`recording.state_hz=200` 是状态落盘频率上限，不能当作设备实测反馈率。统一环境不改变这些设备时序；部署保留各自控制循环，按 checkpoint 的 30 Hz 数据时间网格组织模型观测与目标。

频率差异可通过带时间戳的历史缓存和对齐处理。部署还需分别检查数据年龄、跨模态时间差、延迟抖动与设备执行响应。当前采集实现把相机映射到主机单调时间，低维状态使用 SDK 观测／取出时间，统一时间域并未补偿测量到主机之间的传输延迟。因此报告须区分能直接测得的主机时间差与需要额外测量的设备感知、传输及物理响应延迟，不能把接收时间一致称为真实测量同步。

| 验收项目 | 实施要求 |
| --- | --- |
| 真实反馈与控制周期 | 分别记录双臂、双手和相机的到达间隔、控制周期、丢失／重复样本；报告中位数、P95／P99 和最长间隔 |
| 观测年龄与模态跨度 | 为三路图像、双臂和双手保留来源及接收时间；检查各流年龄、图像两两跨度和图像与状态的时间差。先测量，再根据动作速度及任务容差冻结阈值 |
| 历史观测对齐 | 在已经收到的历史中选取有完整覆盖的时刻，用有效相邻状态插值并匹配图像；记录由对齐带来的额外观测延迟。超过期限仍无法组成合格观测时暂停，不无限等待最慢流 |
| 推理到实际提交 | 测量观测年龄、预处理／传输、GPU 推理、队列等待和 SDK 调用耗时，检查动作的名义时刻及实际提交迟到量；平均延迟和尾部延迟都需通过目标覆盖验收 |
| 双臂双手执行响应 | 同一动作使用共同名义时刻，但分别读取实际反馈，测量跨设备提交时差和目标跟随误差；相同提交时刻不代表物理动作同时到位 |
| 训练与部署时序一致性 | 对照训练数据的时间网格、匹配和插值语义；在线图像长期复用或某一流固定滞后时，检查分布差异。确需调整时间映射或做延迟补偿时，明确实测依据并同时验证训练／部署接口 |

模型观测的时效阈值与驱动健康超时分别配置。现有相机约 0.5 s 的健康超时、手反馈超时和离线修复阈值均不能直接当作模型输入足够新鲜的验收标准。短时闭环增加可控的延迟、抖动或缺帧测试，检查暂停、目标衔接和恢复；新预测替换队列时核对与已执行轨迹的连续性。

Diffusion Policy 作者采用预测动作序列并滚动重规划的方式；后续 RTC 研究指出，单纯分段动作仍会受推理延迟影响，异步执行还需处理新旧动作段的衔接。[Diffusion Policy 作者说明](https://diffusion-policy.cs.columbia.edu/)、[RTC 论文](https://arxiv.org/abs/2506.07339)。本计划据此要求独立控制调度和衔接验收，不将这些研究视为本设备的频率或延迟实测。

适配时明确以下区别：

1. **硬件、动作布局与坐标。** UMI 该环境面向 UR／Franka 与 WSG，每臂为 6 维位姿加 1 维夹爪宽度；其示例设备顺序为右、左。本项目为左臂、右臂、左手、右手的 52 维布局，末端定义为各臂基座系下的法兰。保留本项目 RGB、坐标、关节和动作契约，不能直接使用 UMI 的设备驱动、宽度控制或预处理配置。
2. **指令时间与物理到位时间。** 本数据集的动作标签来自成功提交的绝对指令，时间不是设备到位时刻。采用 UMI 式提前调度前，必须说明延迟标定包含哪些环节，并核对训练标签与部署动作时刻的关系；观测时间修正和动作提前量不能未经核算同时套用。若改变了标签时间语义，应重验数据转换、标签对齐及模型效果，必要时重新训练。
3. **缓存覆盖与超时。** UMI 的 `PoseInterpolator` 将超出时间范围的查询裁到端点，标量插值也使用端点值；其评估脚本在全部动作超过预算时，会把最后预测目标重新安排到后续时刻。本任务保持显式的覆盖／年龄检查，超限暂停，不能把裁到端点的旧状态当作已正确对齐，也不能默认重新发送过期预测目标。
4. **双相机锚点与三路输入。** UMI 的锚点选择遍历 `len(self.robots)` 个相机。本任务需核查全部三路 RGB；最接近锚点不等于通过质量检查，逐路偏移、三路跨度与状态覆盖都要验收。
5. **时间域与依赖。** UMI 部分入口用系统时间安排目标，控制器再转换到单调时间；本项目继续以设备主机单调时间域管理调度和有效期，明确跨进程时间转换。UMI 目录也含同名 `diffusion_policy` 包，参考实现时按模块适配并核对依赖与许可证，避免同时加入两套包路径造成导入覆盖。

阶段 10 的实施顺序据此细化为：先明确观测和动作时间语义并记录原始时戳，测量各流年龄与延迟；再构建通过覆盖检查的观测及目标队列；完成不启用补偿的基线影子推理和闭环记录后，依据实测结果评估单项延迟补偿，比较目标衔接、跟随误差与任务结果。观测对齐、独立控制、定时目标与标定工具优先参考，UMI 示例中的延迟值和超时回退行为不作为本设备的默认值。

## 测试与验收

既有转换、Dataset、Runner 和 GPU 短训练测试已分别在 `bimanual-teleop` 与 `robodiff` 环境验收；阶段 8 建立统一环境后，需在该环境重验与新链路相关的转换、Dataset、Runner、GPU 推理和设备接口检查。

转换测试覆盖真实编码小视频：一／两帧相机缺口可修复，三帧缺口在默认配置下保留边界；参数修改后结果随之变化；单路、多路与主相机缺帧都需覆盖。检查图像来源索引、像素复用、30 Hz 间隔、首尾裁剪、暂停隔离、超限状态间隔、无效四元数、指令过期、旧严格模式兼容和失败时不发布半成品。

暂停测试另覆盖：已复核连续接缝压缩后合并且维持 30 Hz，未经复核或回位／物体改变的接缝仍分段；目标重设保留真实绝对标签；暂停期间不生成伪状态或控制指令；原始时长及拼接位置可追溯，压缩时间不绕过指令新鲜度检查。

Dataset 和 Runner 测试用合成多演示数据验证分组、短片段、剩余缺口、RGB 通道和范围、训练集归一化及旧格式兼容；以带时间索引的动作检查标签对齐，以已知位置、旋转及关节偏差检查指标。图像配置验收覆盖缩放开／关、非默认尺寸及插值方式生效、crop_shape 为 null／有效尺寸、固定评估裁剪，以及非法尺寸或 shape_meta 不一致时报错；同一输入在 Dataset 和 Runner 的确定性预处理结果一致。

Transformer 冒烟核对 GPU 上损失有限、有效梯度及优化器参数分组，训练标签 `(B,16,52)`、完整预测 `(B,16,52)`、执行段 `(B,8,52)`。checkpoint 保存并重载后核对模型、EMA 和归一化参数；固定随机种子检查同一评估输入可复现。

正式阶段报告来源划分、修复参数、配置、checkpoint、指标和样本量。报告不含 NaN 或 Infinity，不将离线误差写成真实任务成功率。
