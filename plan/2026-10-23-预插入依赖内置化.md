# 导轨预插入依赖内置化

目标：复制并移动 `diffusion_policy` 后，现有真机预插入流程、标定和离线验证只读取该项目中的代码、权重及模型，不访问相邻 FoundationPose 或 bimanual-teleop 仓库。任务范围仍截至 20 mm 预插入，不新增接触插入控制。

1. 按用户补充要求，将 FoundationPose 完整源码结构迁入 `third_party/foundationpose/`，包括官方示例、BundleSDF、Docker/构建脚本、文档、本地 workspace 工具与测试及嵌套依赖源码。保留预训练权重、导轨网格、许可证、版本和逐文件摘要；权重使用普通文件。仅排除 Git 元数据、缓存、历史输出、部署归档和工作区的大体积录制数据，不裁剪源码。
2. 将 URDF 运动学、机器人与夹具模型、标定工具及小型离线样本迁入 `third_party/`。设备控制继续复用已有 SDK 快照。
3. 改写实验配置、导入和辅助工具，使资源相对项目定位；提供控制及感知环境说明与本地扩展构建入口。
4. 在隔离副本中验证资源完整性、标定导入、完整模型规划和重放，并运行内置 RGB-D 的 GPU 位姿估计；检查实际模块来源，防止已有环境中的原仓库掩盖依赖。
5. 更新操作说明与验证结果，保留现场标定、目标和障碍物缺失的真实状态。

标准 Python 包、CUDA/驱动与设备 SDK 的安装环境仍由环境文件定义；不复制 Conda 环境。迁移不连接或控制真机。
