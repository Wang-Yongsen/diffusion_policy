1. 安装或合并local_patch中的记录修复。安装器默认只检查哈希，遇到本机不同修改必须合并，不覆盖。补丁已做无硬件单元测试；本机仍须完整影子预检。
2. 实现清单中的V/S及统一初始化adapter。当前包的batch_controller只准备执行单和收集结果，不能冒充已经能够一键启动真机的程序。V/S实际参数必须在本机静态预检中一次冻结，不能看到运行效果再修改。
3. 在本机完成所有假时钟、记录完整性、影子推理及停止路径检查，再运行固定P00至P12。不把适配或预检拆成新的机器人实验，不把准备工作交回用户逐项讨论。

## 固定13段

| 内容 | 数量 |
|---|---:|
| 示范观测驱动并被动记录真实观测的校准段 | 1 |
| 原实时输入和原同步方式 C0 | 3 |
| 单一冻结的视觉修正V和原同步方式 C1 | 3 |
| 原实时输入和实测稳定采样S C2 | 3 |
| 相同视觉修正V和相同稳定采样S C3 | 3 |
| 合计 | 13 |

每段正式运动最多10秒或24次模型决策，先到者结束；所有段有效运动时间合计上限130秒，复位、预热、预检另计。V/S可能减少墙钟内的决策数量，因此同时按时间、公共决策前缀和任务阶段比较。

三个重复的种子分别42、43、44；每个重复内四条件共享同一采样起点，按清单预定的平衡顺序运行。所有段，包括校准段，共用相同双臂姿态、关节及双手初始化，不能再保留校准独有的接近首预测动作流程。

第50轮EMA、30Hz、两帧观测、8步动作、DDIM8及原执行约束保持固定。不将训练频率改成15Hz，不通过改增益或解除约束伪装修复。

V必须是对当前真实画面可重复应用、保留场景几何的单一候选，保存参数、公式或实际成像设置和离线依据；不使用示范画面替代实时画面控制机器人，也不把111当作必达亮度。若现场无法构造有依据的V，预检阶段就明确报告该条件不可辨识，不能伪造V已冻结或盲目启动该条件。

S使用实际反馈检查一段有界稳定窗口，获取新观测后推理，返回时再核对平移、旋转与双手变化；超出冻结容差则有界重采样或停止。S不重置伺服内部状态，也不改变原设备目标刷新。稳定等待最多2秒、每次决策最多2次重采样，参数在首次运动前锁定。

现场仍由用户按既有流程开始、停止和复位。本服务器没有已建立的本机机器人执行通道，13段并未在服务器执行。

这些补丁是记录正确性与可比性修复，不是已经验收的机器人抓取修复。V/S本机adapter、候选参数及硬件验证仍需本地完成，包中明确标识未冻结状态。

## 一次交付与结束条件

整批必须包含13个slot终态、全部决策原始观测和RNG、最后拒绝块、命令及反馈、状态汇总与故障、冻结参数、实际源码及哈希、完整初始化差异、人工介入标记。

报告必须一次给出V主效应、S主效应、V与S交互，四条件三次重复各自的外伸、接近导轨、抓取结果；10秒短片段不自动等同完整任务成功。没有纠偏标签的自然离轨窗口只报告模型行为，不伪造恢复准确率。

若无效记录导致不能比较，明确列明哪一slot、哪一字段或哪一实现不合格；若数据完整但不能唯一归因，给出本批次支持与不支持的机制。两种情况都不在13段后自动追加，不默认再要求用户补一小段。
