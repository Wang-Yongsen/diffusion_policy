# RL-100 在 Tianji 和 Wuji Hand2 上的实施指南

日期：2026-10-18。以下以两个仓库现有的双臂导轨放置任务为例；更换任务时重新定义成功条件、起始分布和重置过程。

建议保留三路 RGB、52 维绝对 EEF 动作、现有遥操作和设备执行接口，从现有约 50 条示范建立真实闭环基线，再增加 RL 数据采集、价值学习和扩散策略更新。实施顺序为：**闭环验收 → 示范初始化 → 迭代离线 RL 与数据扩充 → 少量在线 RL → 按延迟需求蒸馏 → 独立评测**。

50 条示范可以启动模仿学习和接口验证；是否足够进入 RL，要看真实观测驱动时是否已有可重复的自主成功。数据预算先按人工示范累计 100–150 条、迭代离线阶段新增 400–800 条机器人轨迹、在线阶段新增 100–300 条轨迹安排，逐轮看收益调整。这是针对本项目的首轮预算，不是论文给出的收敛保证。

## 论文方法和数据预算

[论文 v4](https://arxiv.org/abs/2510.14830v4) 更新于 2026-03-10。核心算法是先用示范做扩散行为克隆，再用 IQL 的 Q−V 优势进行离线更新，以学习到的转移模型和 AM-Q 离线策略评估决定是否推进参考策略；在线阶段换用新交互和 GAE 优势。离线、在线都对去噪步骤使用 PPO 裁剪目标，并共享环境层的优势。每轮扩充数据后重新做模仿学习。可并行蒸馏为单步一致性模型。

直观上，Q 评价某个动作好不好，V 评价当前状态通常能做到多好，Q−V 决定该提高还是降低相应行为的概率。OPE 是模型估计，仍须用真实评测验证策略是否改善。

## 第一步 定义任务结果并验收真实闭环

先写清楚：物体初始位置和朝向范围、允许变化的导轨位置、最终放置标准、保持时间、超时上限、失败和人工接管的判定。若示范包括成功后的回程，明确任务在放置完成时终止，或将回程单列为另一阶段，避免奖励落在无关回程末尾。

沿用已验证的 checkpoint、预处理、归一化器和执行模式，完成 20–30 次真实观测闭环试验，记录成功率、失败阶段、完成时间和接管次数。示教观测回放只能验证该输入下的预测及执行，不能替代真实相机闭环。

项目已有[观测差异排查计划](/home/yuchen/project/diffusion_policy/docs/tianji-rail-next-actions-after-results-20261017.md)。先完成其中输入、请求目标、命令 FK、控制器反馈与实测反馈的对应检查，再判断剩余问题是否适合用 RL 改进。观测错位、错误坐标或下发接口问题应先修复。

带噪声采集前还需收紧一个具体配置：当前[真机配置](/home/yuchen/project/diffusion_policy/diffusion_policy/config/tianji_rail_real_eval.yaml)将双臂 workspace 设为每轴 ±1000 米，近似不限制位置。将其换成任务实测范围，再确定探索边界。52 个动作维度的物理量不同，不直接把官方归一化噪声上限照搬到手和双臂。

完成条件：相同设置下能够重复获得自主成功，或已明确失败来自策略能力；所有结果都使用真实观测，接管独立标注。

## 第二步 整理现有示范并补覆盖

先检查约 50 条示范的相机身份、方向、单位、时间对齐、暂停缺口和最终任务结果。采集文档记录了 10 月 14 日腕部编号调整、10 月 16 日主相机更换，旧数据按各自元数据核对，不能仅按 camera_1、camera_2 名字混合。

按完整来源示范留出 5–10 条作验证；同一示范的所有连续片段进入同一分区。暂停、丢帧切出的 segment 不能算作新示范，也不能自动认定任务成功。另保留真实机器人评测，与离线验证分开。

补数据时优先增加当前失败位置附近的接近、重新抓取、轻微放偏后恢复，以及不同初始姿态；人工示范累计先做到 100–150 条。若任务只有固定起点且已稳定成功，可先不扩到该数；若起点、手形和物体变化大，则按覆盖缺口增加。

完成条件：得到版本固定的示范数据、来源划分、成功定义和按阶段整理的失败清单；不再仅以“条数够了”作为进入下一阶段的依据。

## 第三步 建立扩散模仿学习基线

优先保留现有 Transformer、三视角输入和 52 维动作，保持 2 帧观测、16 步预测、8 步执行、DDIM 8 步。当前模型已经使用 epsilon prediction。先用同一配置建立可比较的 BC 策略，避免同时改变网络、图像尺寸、动作表示和控制模式。

推荐在独立训练模块中接入 RL-100 的采样及更新方法，现有 BC 类和工作区继续作为对照。官方 2D Actor 支持的去噪骨干包括 U-Net、MLP 和 Skip-Net，没有当前这个 Transformer 的直接权重加载接口；复用本地 Transformer属于算法适配。若优先使用官方完整训练后端，则另训练同数据的 2D U-Net BC，不强行映射 Transformer 权重。

环境以本地现状为起点隔离：训练仓库为 Python 3.10、PyTorch 2.7.1、diffusers 0.11.1；官方安装文档采用 Python 3.8、PyTorch 2.4.0、diffusers 0.33.1。可从现有训练环境克隆独立的 Tianji RL 环境，逐项适配 scheduler；不直接覆盖遥操作或现有训练环境的依赖。

完成条件：保存 BC checkpoint、normalizer、预处理、数据版本、真实闭环结果和失败视频；后续所有 RL 轮次与这份基线比较。

## 第四步 增加完整 RL 轨迹和奖励

当前 [TianjiRailImageDataset](/home/yuchen/project/diffusion_policy/diffusion_policy/dataset/tianji_rail_image_dataset.py)只返回 obs 和 action。新增 RL Dataset，至少提供以下信息。

| 数据 | 用途和语义 |
| --- | --- |
| obs、next_obs | 决策时真正使用的三路图像和实测状态；保持各源时间戳 |
| action、executed_action | 策略请求的动作块与实际接受、执行的目标分别记录；后者不冒充策略采样值 |
| reward、success | 首版用成功终止 +1，其余 0；成功标签独立于录制是否正常保存 |
| terminated、truncated、end_reason | 区分任务结束、时间上限、接管、记录缺口与设备中止；据结束原因决定是否 bootstrap |
| duration、execution_mask | 真实决策间隔、每个动作实际执行的范围、被覆盖或过期的步骤 |
| source_episode、round、policy_version | 追溯来源，防止重复追加和验证集泄漏 |
| denoising_chain、old_log_prob | 在线 PPO 所需的去噪状态、采样转移、scheduler 设置和行为策略概率 |

原始遥操作没有去噪链是正常的，可用于 BC、IQL 和转移模型。在线策略轨迹则必须保存或能准确重建行为策略的去噪转移概率；仅保存最终 52 维目标不够。

现有 `--record-observations` 只循环保存少量图像窗口，SessionTrace 又有固定容量，均不直接作为长时训练缓冲。复用其时间戳和事件关联方式，另建完整、可校验的 rollout writer；记录丢失的片段不悄悄用于训练。

保留失败和接管数据供价值学习，接管后由人控制的动作明确另标。BC 重训练可先使用成功轨迹和人工确认的有效恢复片段；这是本项目的保守数据筛选方案，不等同于论文算法中直接对扩展数据集做 IL 的唯一实现。

人工结果可复用现有 y 成功、n 失败、p 接管。录制完整、S 保存、阶段 B 标记、数据 segment 结束都不是成功信号。遇到缺帧或暂停缺口，不连接 gap 两侧的 next_obs。

完成条件：先用少量完整轨迹验证奖励、边界、下一观测、接管标签及时间戳均正确，再扩大采集。

## 第五步 接入带概率的去噪采样

当前 [Transformer Policy](/home/yuchen/project/diffusion_policy/diffusion_policy/policy/diffusion_transformer_hybrid_image_policy.py)只调用 scheduler.step 并返回动作，没有给 PPO 返回每步去噪概率。需要增加随机 DDIM 转移，给受训转移设置已知的非零方差，并保存高斯转移的 log probability。复用官方 [DDIM scheduler 实现](https://github.com/Lei-Kun/RL-100/blob/main/RL-100/rl_100/unidpg/diffusion_policy/diffusers_patch/ddim_with_logprob_dpok.py)时，对齐本地 diffusers 版本、时间步、末步处理和张量维度。

PPO 比率来自同一去噪转移在新旧策略下的概率之比。离线优势使用 Q−V，在线使用 GAE；同一个环境优势用于该动作的多个去噪步骤。最终动作 MSE 不能替代这个比率。

对本项目尤其要核对三点：

1. 模型预测 16 步，返回切片 [1:9]；明确哪部分随机变量参与策略目标，未执行维度不得被当作额外环境交互。
2. 8 步 × 52 维已经是 416 个动作分量；概率聚合方式、归一化和 PPO 裁剪严格一致，不随意把求和改成平均来掩盖不稳定。
3. 本地 Transformer 有 attention dropout。计算新旧概率时使用一致的网络模式、确定性预处理和冻结的旧策略，不能让 dropout 或随机裁剪伪造概率差异。

接真机前用离线数据完成三个检查：同参数时 PPO ratio 接近 1；采样时保存的 log probability 能被重算；无效概率、极端 KL 和 NaN 可及时发现。随机探索在归一化动作空间定义，并检查反归一化后的双臂和各手关节幅度；去噪方差裁剪与设备动作限制是不同层次。

## 第六步 运行迭代离线 RL

每轮按同一顺序执行：

1. 从本轮示范和机器人轨迹训练或更新 BC 初始化。
2. 固定本轮视觉编码器，训练 IQL 的 Q、V，以及用于 OPE 的潜在状态转移模型。将本地 12 维 EEF 和 40 维手状态正确接入特征，不能只改官方 agent_pos 的字段名。
3. 用离线 Q−V 优势对扩散去噪策略做小步 PPO 更新，通过 OPE 门控推进参考策略。
4. 用独立真实试验验证改善，再带受限探索采集新轨迹，成功和失败都记录。
5. 合并成新数据版本，重新做 IL，进入下一轮；重新训练视觉编码器后，旧缓存特征、价值函数和转移模型须更新或重新核验。

先采 50–100 条形成第一轮 RL 数据，首轮与第二轮合计看 150–300 条的变化；有效后每轮追加约 100–200 条，迭代离线阶段总预算先预留 400–800 条。这些数按本任务工程预算设置，不是论文逐轮采集配方。

初始可参考官方离线 Actor 学习率搜索范围 1e-6 到 1e-5，从较小值开始，一次只对比少量设置。BC 学习率不直接照搬为 RL Actor 学习率。Q、V、转移模型分别选学习率和训练终点。若 OPE 分数持续提高而真实成功率下降，先查模型外推、奖励及执行对齐，保留上一份真实表现更好的策略。

完成条件：真实闭环成功率和完成时间对 BC 有稳定改善；失败集中到少数可复现的情况。是否进入在线阶段由这些证据决定，不要求照搬论文达到某个精确百分比。

## 第七步 小预算在线 RL

从离线改善最好的策略开始，每批采集新轨迹，用 GAE 计算优势，再做少量 PPO 更新。先预算 100–300 条轨迹，若仍有收益再扩充。论文个别任务的在线采集超过 700 条，不能把“少量在线”理解为固定几十条。

这里的关键是现有执行语义：[runtime](/home/yuchen/project/diffusion_policy/diffusion_policy/real_world/tianji_policy_runtime.py)的 async 模式会丢弃过期动作并用新预测替换未来队列；sync 模式执行完整段，但推理期间保持上一目标。因此不能统一假定“每次预测都执行了完整 8 步且用时固定”。

优先沿用已经通过闭环验收的执行模式，不在第一次 RL 试验中同时换模式。把真正执行的动作块、结束观测、时间长度和奖励绑定成一次转移。固定 c 步执行时，块奖励为各步折扣和，下一状态的折扣为 gamma^c；若有额外等待或可变执行长度，则采用明确的时间约定或半马尔可夫折扣，并用于离线数据、价值训练和在线更新。若控制器状态会影响结果，将上一接受目标、队列状态等必要信息纳入学习状态或明确限制为固定执行协议。

所有试验从结果按键得到结束标签，重置过程不混进任务轨迹。策略请求、设备接受的命令及实测状态分层保存；PPO 的 old_log_prob 始终对应原采样随机变量，不能事后对限幅或 IK 变换后的目标重新套原高斯概率。

完成条件：新策略在固定测试分布下稳定改善，且更低失败率没有靠延长超时或增加人工接管得到。

## 第八步 按延迟需要蒸馏

先测三路图像读取、编码、8 步去噪、进程传输和调度各自耗时。只有模型计算是主要瓶颈时，才优先做 DDIM 到单步一致性模型蒸馏；相机、传输或执行等待仍需分别处理。

论文可在离线、在线训练中并行蒸馏；本项目首版可先让多步教师达到可靠水平，再接入蒸馏，减少同时变化的因素。蒸馏后独立比较成功率、姿态连续性、恢复能力和端到端耗时。原论文没有评测榨汁取出任务的 CM，因为该任务的 IK 不连续性使单步策略更敏感；单步部署不是所有任务的必选项。

## 第九步 独立评测并决定下一轮

每轮用同一套初始条件分布作 20–30 次快速对照；最后冻结策略，至少做 100 次独立真实试验，记录成功数和分母、完成时间、接管、超时及设备中止。若要支持更高可靠性结论，需要更多独立试验与置信区间；100 次全成功不能推出真实成功率等于 100%。

另做位置偏差、物体或导轨变化、抓取偏差和轻微扰动测试，报告各条件样本数。扰动恢复测试和固定条件评测分开列出，避免平均数掩盖某类失败。

采集工时用真实任务估算：小时数约为轨迹条数 ×（平均任务秒数＋平均重置和标注秒数）÷3600。例如每次任务 30 秒、重置和标注 30 秒，600 条机器人轨迹约 10 小时，未计模型训练和排障。实际周期应由前 20–30 次试验测得。

## 最小实施顺序

| 顺序 | 交付物 | 主要接入位置 |
| --- | --- | --- |
| 1 | 真实闭环 BC 基线和明确的成功标签 | 现有真实评估入口、结果按键与观测诊断 |
| 2 | 完整 RL 轨迹和新的 RL Dataset | 真机 runner、独立 rollout writer，保留现有 BC Dataset |
| 3 | 带去噪链和 log probability 的 Actor | 现有 Transformer 外的 RL 适配类与 scheduler |
| 4 | IQL、转移模型、OPE 和离线更新工作区 | 新建训练模块，复用视觉特征和本地观测动作契约 |
| 5 | 每轮数据版本、IL 重训练和真实对照 | 新训练配置和数据合并工具 |
| 6 | 单机器人在线 GAE 与 PPO | 已验收的执行协议和结果标注 |
| 7 | 可选单步蒸馏和独立最终评测 | 教师、学生分别评测 |

官方 [README](https://github.com/Lei-Kun/RL-100) 的示例任务主要用于验证训练流程，不能只把任务名改为 Tianji 就运行。核对的官方提交为 `6b6afceb7eb12525398207b5d6e66908863dc385`；部分 DDIM 脚本仍含参数扫描，以及 `after_offlin` 与训练逻辑 `after_offline` 不一致的设置。根据本地任务生成独立配置，先核对入口、阶段标志和实际生效参数。

算法项目保留设备快照；遥操作项目继续负责示范采集。不要把遥操作项目当前修改自动同步进算法项目的 third_party 快照，先核对实际导入来源和设备配置。现有两个仓库均有未提交修改，新训练模块和数据版本与当前诊断工作分开管理。
