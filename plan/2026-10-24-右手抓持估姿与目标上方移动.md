# 右手抓持估姿与目标上方移动

目标：右手闭合后重新估计导轨位姿，显示当前、目标和目标上方位姿，保持抓握并仅移动到目标上方。

- 复用掌部位置、RGB-D 几何及 CAD 尺寸生成 FoundationPose 初始化区域；不需要人工 mask，不使用 GPT、SAM 或额外检测模型。
- 复用相机到左基座标定，通过已验证的 URDF/SDK 固定基座关系换算到右基座。
- 关闭后重新初始化，按图像采集时刻插值右臂反馈，计算并平均 `T_F_O = inv(T_R_F) @ T_R_C @ T_C_O`。
- 目标上方定义为右基座 `+Y`，默认 0.05 m；方向与目标导轨一致。先抬升，再移动并调整方向，末端由导轨目标和实测抓持关系反算。
- 接料程序增加 `--move-above`，可用 `--already-held` 从已抓持状态开始；默认接料行为保持兼容。只使用同一个右臂、右手控制实例。
- 输出实时图像、抓持后观测、右臂规划和到位验证。到位后持续保持，不下降、不插入、不松手。
- 不停止或操作当前正在运行的接料进程。本轮验证以离线几何、真实 SDK IK/FK、模拟设备流程和合成 RGB-D GPU 回放为主。

限制：沿用现有 SDK 限位与伺服；没有场景碰撞规划。合成数据和软件验证不代表真机完成。

实现入口：`workspace/rail_pose_insert/receive.py run --motion --move-above`。
已持轨启动增加 `--already-held`；高度用 `--above-height` 覆盖。

## 验证结果

- 新增 11 项测试通过，覆盖非对易坐标变换、右基座 +Y 上方偏置、采集时刻插值、右臂 IK 路由、旧帧/回放拒绝、不可达时不下发、视觉到位/超差、既有控制线程、完整 G 闭合后搬运，以及已持轨启动不张手。
- 使用真实标定与目标、构造抓持关系进行官方 SDK IK/FK 离线规划，通过；不代表实际抓持关系已测得。
- 原 CartesianServo 在 200 Hz 数值回放中完成 757 步，构造终点误差约 9.7e-8 m / 3.9e-9 rad。该数据不包含真机误差。证据：`outputs/above_validation_20261024/servo_replay.json`。
- 配置及 GPU 预检通过，OpenCV 窗口打开、显示和关闭通过；叠图包含当前/目标/目标上方三组 CAD 框。
- 合成 RGB-D GPU 回放 5 帧均完成自动初始化/跟踪，没有使用存储 mask。**精度未通过**：已知真值位置误差约 14.7–19.5 mm，旋转误差由 2.6° 增至 20.9°。默认静止一致性检查会拒绝末尾 3 帧，不能把这组输出用于继续搬运。证据：`outputs/above_validation_20261024/gpu_accuracy.json`。
- 全量实验测试 73 项中 71 项通过；独立打包项存在 2 个既有失败：Conda 环境 editable namespace 仍查找源项目 `diffusion_policy.config`，被迁移测试的访问保护拒绝。已在临时副本恢复 HEAD 的 core/planner 后复现相同失败；没有修改或重装环境。
- 本轮没有连接机器人、驱动机械臂、停用手或停止原接料进程。

## 使用与遗留问题

当前进程不会热加载新功能，需切换到新命令。原实例退出会停用右手，切换时需支撑导轨；`--already-held` 按实测手型接管，不保证复现旧控制器的握持力。

真机抓持后估姿、遮挡下的方向一致性和到位精度仍待现场验证。合成无纹理 CAD 上观察到的漂移已记录，未以“有效帧数”冒充精度通过。当前停止点只到目标上方，后续下降和插入没有实现。
