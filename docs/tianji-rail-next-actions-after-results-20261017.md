# 导轨任务结果后的最小修复与验证计划

日期：2026-10-17（UTC+8）  
执行方：本地 AI；项目 `/home/yuchen/project/diffusion_policy`  
目的：确定真实观测闭环在哪一层首次偏离，再做对应修复。

## 当前决策

本轮先实现完整记录和离线对比，再沿用用户已有的人工开始和停止流程做两段短测试。暂不启动新训练，也不同时更换推理模式、执行参数、相机设置或控制频率。旧完整计划中已通过的权重、初始静态输入和预处理一致性检查不再重复。

最有区分力的实验是：**在已成功的示范观测驱动过程中，同步保存真实图像和反馈，结束后才用真实观测离线推理。** 这能观察机器人沿正确轨迹运动时，真实输入是否已经令预测偏离。

“请求目标与实测位置相差几厘米”只是一项现象，不能直接定性为伺服故障。先拆分命令生成、控制器目标、实际运动及观测时间。

## 固定基线

- 第50轮 EMA，SHA256 `575b901e0aa801437046789d3ae626969943043f0d8a2307acb88d4b158286d3`；按哈希选文件，不使用会被训练覆盖的文件名来判定版本。
- 30 Hz、两帧观测、16步预测、8步执行、DDIM 8、现有 sync 模式；模型处于 eval，使用 checkpoint 原有 normalizer。
- 沿用同一套相机身份、方向和图像处理；左臂原生轴为 +X向前、+Y向下、+Z向外。
- 起点对齐到选定成功回放的完整状态：左右臂位置及姿态、左右手实际关节反馈。记录全部差异，不只比较左臂 XYZ。若无法对齐手形或姿态，明确该变量没有控制住。
- 比较段覆盖起步到接近导轨，通常约5至10秒，以任务阶段为准。无人递送导轨、扶手或拉动机器人；实际人工介入的时间必须标注。
- 所有运动沿用用户人工操作；AI先完成代码、离线验证与记录预检，不自行接合或启动运动。

## 第一步 补齐记录并离线验证

先保存本机 git commit、完整 dirty diff，以及实际导入的 eval、env、runtime、推理进程、Cartesian executor、servo、driver 的路径和源码哈希。现有 session 的同一个 commit 加 dirty 不能证明源码完全一致。

每条记录使用单调时钟、prediction_id、chunk_id、step_id、command_id 和反馈采样序号关联。记录以下层次：

| 层次 | 必须保存的量 | 用途 |
|---|---|---|
| 输入 | 每次决策的三路两帧原始 RGB、双臂 EEF、双手关节、query/anchor、各源时间与状态插值括号 | 重建真正进入模型的观测 |
| 模型 | 当次完整8步动作、CPU/CUDA采样前 RNG、推理各阶段时间 | 区分随机差异与输入差异 |
| 调度 | 8步各自计划时间、实际submit时间和回执 | 判断步骤是否调用、拒绝或过期 |
| 伺服命令 | 实际接受的 q_cmd、FK(q_cmd)、limited、progress、timing_status | 判断请求目标被伺服约束改变多少 |
| 控制器 | 反馈中的 controller_target_rad、源采样时间；不可用则明确缺失 | 判断控制器收到的目标与主机命令是否一致 |
| 实测 | 双臂实际关节、对应FK、双手实际关节及原始采样时间 | 判断实际跟踪与状态变化 |

服务器接口提示：`TianjiCartesianExecutor.applied_poses` 是已接受关节命令的 FK，不是实测位置；`tracking_status.position_error_m` 是请求目标到命令 FK 的剩余距离，也不是实际跟踪误差。必须核对本机源码再接入。

优先复用 driver 的 `start(sink=...)` observer 以及 `tianji_command_submitted` 事件，它们已提供请求位姿、命令FK与关节命令。记录实际用于提交的反馈快照和时间，不事后读取另一时刻的 `get_latest()` 来冒充同一条反馈。日志丢失数必须报告；丢失关键窗口时，不能据此判定根因。

当前 servo 的 `actual_rad` 参数主要作合法性检查，规划状态来自已接受命令。不要为了让曲线好看而逐tick重置为实际关节，这会改变速度、加速度及约束状态。

保存每个决策周期的完整输入，不再只保留前三和最后三组。短片段可使用预分配、有界内存缓冲，运动结束后落盘。控制线程中不压缩图像、不写NPZ、不额外执行重型FK；缓冲不足则明确标记记录无效，不能阻塞控制。

先用保存输入、假设备和假时钟验证：记录开关不改变动作、索引或时间计算；提交回执与命令正确关联；无数据或不支持字段不能填0伪装正常。已有预处理一致性只做必要的回归。

交付一张时间对齐图：模型/调度请求、命令FK、控制器目标FK（若有）、实测FK；另画双手目标与反馈，以及推理期间的实际位移。由既有反馈计算FK在离线完成。

## 第二步 成功回放时采集真实输入

1. 选择此前已经成功的同一段示范观测驱动方式，优先覆盖左手接近导轨。不要临时替换成另一种关节或标签回放。
2. 在每次决策时保存当时使用的示范观测，并独立取得实际对齐后的真实观测。继续只下发原成功路径的模型动作；真实观测不参与控制。
3. 用户按原流程运行短片段。记录功能先完成预检，避免额外推理或磁盘操作拖慢这次对照。
4. 测试结束、设备关闭后，同一设备和模型分别对示范输入与真实输入离线预测，至少用三个配对种子。固定设备上的共同 RNG 或初始噪声；CPU与CUDA相同seed不能当作同一噪声。
5. 保存全部8步和52维结果，比较位置、SO(3)姿态、手形与推进方向，同时报告同输入不同种子的波动。
6. 先核查实际机器人是否跟随了成功轨迹，再按实际状态和任务阶段配对。同步停顿会改变墙钟进度，不能把真机第5秒直接配示范第5秒；也不能跨到示范回程阶段找位置近邻。

先完整评估这一段，不新增静态2×2矩阵。若真实输入只在某个阶段产生稳定分歧，再仅针对该窗口拆分相机或状态字段。

## 第三步 相同条件下的短真实闭环

沿用第二步的完整起点、场景、模型及执行配置，切换为真实输入，用户运行一段无人辅助的短闭环，逐决策保存完整记录。覆盖首次明显偏离即可，不需要为凑30秒继续运行。

以成功回放的误差和相位滞后为基线，定位最早分歧发生于：模型输出、命令生成、控制器目标、实际运动，还是观测时间。单次结果决定下一分支；选定修复有改善后，再补至少三次独立重置的同条件验证。

| 第二和第三步的结果 | 对应处理 |
|---|---|
| 只要完整初始化，真实闭环就恢复 | 固化双臂姿态、双手形状和稳定状态的启动检查；暂不重训 |
| 成功回放中，请求到命令FK已有大幅差异 | 检查伺服约束、关节/腕部边界、目标跳变及配置；用同一段请求离线复算，不直接提高增益或解除限制 |
| 命令FK合理，但控制器目标或实际反馈明显滞后 | 检查发送、控制模式、驱动、初始化残余运动及反馈时间；正常动态滞后与异常以成功基线区分 |
| 实际轨迹及阶段接近示范，但真实输入离线预测稳定偏离 | 定位具体输入差异；转换/时间错误修部署，内容泛化不足再补数据或做有依据的增强 |
| 成功轨迹上的真实输入预测正常，真实闭环却逐步走偏 | 检查输入到下发间的实际运动和时序；排除后，优先补离轨恢复数据 |
| 没有完整首次偏离窗口，或期间有人递送导轨 | 只描述观察结果，不做根因归属；补足缺失窗口即可 |

如果跟踪分支仍不清楚，从已核验的成功回放截取无接触的短请求序列，固定初始状态、全部目标与调度时间，先用假设备离线回放。必要时才由用户运行这一固定序列，把模型随机变化从执行链验证中移除。

## 同步时序的条件修复

当前 sync 按调度时间结束动作块，保持最后命令，再采样和推理；**保持目标不等于机器人已经静止。** `retimed_actions` 重新计时隐含推理期间状态近似不变。如果机器人仍在追赶最后目标，推理返回时输入可能已经过时。

033的早期第1至4块（从0计数）已验证：从输入锚点到接近返回时的反馈，左臂实际位移约15.0、11.3、10.4、40.8毫米，间隔约170、193、178、195毫秒；输入与锚点时刻实测本身相差不足0.2毫米。因此这批观测在推理期间确实发生了运动，而非仅把过期反馈算作坏输入。这是具体可检验的部署假设偏差，尚未证明是旧028的唯一主因。

继续测量每次推理从输入锚点到返回、下发时的实际双臂/双手变化，不能只比较旧反馈或仅看推理耗时。

若这个机制在首次偏离时成立，可实现一个诊断开关：块结束后，在保留原有约束和看门狗的前提下，等待实测状态进入短暂稳定窗口，再取新观测推理；返回时再次核对实际位移，超过约定容差则不发布该过时预测。阈值由正常静止反馈噪声和设备重复性设定，等待与重试都必须有上限、超时退出；不能等待不可达目标而无限阻塞。先用假反馈/假时钟检验静止、推理期间运动、反馈缺失及超时路径，再由用户做相同起点短对照。

该开关用于隔离“运动中旧观测被重新计时”的影响，不预先当成最终方案；更长停顿也可能降低表现。若证实延迟是关键，再针对耗时阶段优化采样、复制、IPC和推理，并验证同输入动作一致性。

不要直接把sync换async当作修复。当前8步30Hz的最后目标相对锚点约233毫秒，实测推理约170至180毫秒，留给未来动作的覆盖很短；异步方案必须先离线验证观测年龄、过期步、下一次预测到达和覆盖连续性。延迟补偿或执行窗口设计须单独评估，不能仅修改字符串。

## 何时改变训练

只有前述结果支持相应分支，才进入训练工作：

- 正确位置、姿态、手形和阶段下，真实图像仍导致稳定错误：补充对应现场条件，增强只针对已证实的视觉差异并保持几何关系。涉及人工递送的038后段不能作为无人抓取的错误标签。
- 接近示范时正常，稍偏离后无法恢复，且执行与时序已可接受：采集真实偏离状态下的人类纠偏轨迹，标明接管与恢复阶段。不要随意修改状态后沿用原动作标签。
- 认为多训几轮或换checkpoint有效：先用保存的同一真实观测窗口离线筛选候选，再以相同起点、配置进行独立闭环验证。loss更低本身不是验收条件。

新增数据按采集会话或场景划分训练/验证，避免相邻窗口泄漏。评价至少区分自主外伸、实际抓住导轨和完整任务成功；人工递送后的完成不能算自主抓取。
